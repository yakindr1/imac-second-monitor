# iMac 2011 как второй экран Windows

Windows создаёт отдельный виртуальный экран, Sunshine передаёт его изображение по сети, а Moonlight показывает его на iMac. Окно можно перенести вправо с основного монитора Windows, и оно появится на Mac. Подключённые к Mac мышь и клавиатура управляют Windows через тот же сеанс.

Это видеопоток со сжатием и задержкой. Провод Ethernet соединяет компьютеры по сети. Он не передаёт HDMI, не включает Target Display Mode и не требует перепрошивки iMac. SSH использовался для настройки; изображение через SSH не передаётся.

## Проверенная система

| Сторона | Проверенная конфигурация |
| --- | --- |
| Приёмник | iMac 27″ Mid 2011, Core i7-2600, Radeon HD 6970M 1 ГБ, экран 2560×1440 |
| Система Mac | macOS Ventura 13.5.1, OpenCore Legacy Patcher 0.6.8 |
| Клиент | Moonlight Qt 6.2.0 |
| Передающий компьютер | Windows 11, NVIDIA RTX и встроенная графика Intel |
| Сервер | Sunshine 2026.914.233613 |
| Виртуальный экран | Virtual Display Driver 25.7.23 beta |

Проверены расширенный рабочий стол 2560×1440 при 60 Гц, поток H.264 с NVENC на RTX, управление с Mac и переключение между проводом и Wi-Fi. В режиме дублирования получился общий рабочий стол 1920×1080 с захватом через Intel и QSV. Это результаты одной системы. Полный запуск обоих компьютеров после выключения ещё не проверен. Установка Ventura и восстановление OCLP в это руководство не входят.

## Установка программ

Скачивайте программы из официальных релизов. Для повторения проверенной связки используйте [Moonlight 6.2.0](https://github.com/moonlight-stream/moonlight-qt/releases/tag/v6.2.0), [Sunshine 2026.914.233613](https://github.com/LizardByte/Sunshine/releases/tag/v2026.914.233613) и [Virtual Display Driver 25.7.23 beta](https://github.com/VirtualDrivers/Virtual-Display-Driver/releases/tag/25.7.23). Обновления могут менять интерфейс и поведение; проверенную версию не следует автоматически считать рекомендацией на будущее.

На Windows установите Sunshine и виртуальный дисплей по инструкциям проектов. Виртуальный аудиодрайвер для изображения не нужен. На Mac откройте официальный универсальный DMG Moonlight и перенесите приложение в «Программы». Проверенная сборка содержит Intel-версию и запускается на указанной Ventura. Не отключайте Gatekeeper ради неизвестной копии приложения.

Откройте локальную панель Sunshine, задайте собственные данные входа и выполните сопряжение: добавьте компьютер в Moonlight и подтвердите показанный PIN в Sunshine. Подробности есть в [официальном руководстве Moonlight](https://github.com/moonlight-stream/moonlight-docs/wiki/Setup-Guide). Не переносите чужие сертификаты или готовые настройки сопряжения.

## Прямой провод и резервный Wi-Fi

Для первого запуска удобнее Ethernet. Пример отдельной подсети:

| Параметр | Windows Ethernet | iMac Ethernet |
| --- | --- | --- |
| IPv4 | `192.168.50.1` | `192.168.50.2` |
| Маска | `255.255.255.252` (`/30`) | `255.255.255.252` (`/30`) |
| Шлюз | пусто | пусто |
| DNS | пусто | пусто |

Сначала убедитесь, что `192.168.50.0/30` не занята домашней сетью, VPN или другим адаптером. Это адреса для примера. Изменять нужно Ethernet, сохраняя привычный Wi-Fi для интернета. Не назначайте прямому соединению выдуманный шлюз.

Разрешите Sunshine входящие соединения в брандмауэре Windows для нужной локальной сети. Не открывайте его порты в интернет. Добавьте в Moonlight проводной адрес Windows и проверьте соединение до настройки резерва.

Для Wi-Fi используйте имя своего ПК, например `WORKSTATION.local`, либо закрепление адреса на роутере. Не зашивайте случайный DHCP-адрес в постоянную настройку. Проверяйте фактический интерфейс потока: выбранный адрес в команде Moonlight ещё не доказывает, что видео идёт по проводу.

## Отдельный рабочий стол 2560×1440

В Windows откройте «Параметры → Система → Дисплей» и нажмите «Определить». Найдите виртуальный экран по его данным, а не по номеру из чужой инструкции. Нумерация меняется после установки драйверов и подключения мониторов.

Выберите «Расширить эти экраны». Оставьте физический монитор основным, виртуальный расположите справа. Для виртуального задайте 2560×1440 и 60 Гц в дополнительных параметрах дисплея. Проверьте, что окно действительно перемещается на него и обратно. Если интерфейс слишком мелкий, измените масштаб Windows, сохранив разрешение 2560×1440.

В Sunshine выберите захват виртуального экрана. В Windows параметр `output_name` использует индивидуальный `device_id`, то есть GUID конкретного дисплея. Возьмите его из списка устройств Sunshine; не копируйте чужой GUID. Формат описан в [документации Sunshine этой версии](https://docs.lizardbyte.dev/projects/sunshine/v2026.914.233613/md_docs_2configuration.html#output_name).

В проверенной конфигурации автоматическое изменение дисплеев Sunshine отключено: `dd_configuration_option = disabled`. Разрешение и частота задаются в Windows, чтобы подключение клиента не перестраивало рабочий стол. После изменения источника захвата переподключите сеанс и убедитесь, что показывается нужный экран.

## Настройки Moonlight для старой Radeon

Radeon HD 6970M не поддерживает Metal. На этой системе рабочим оказался H.264 с программным декодированием и SDL/OpenGL. Кодирование выполняет Windows, декодирование выполняет процессор iMac. Выбор NVENC на сервере не включает аппаратный декодер на Mac.

Для рабочего режима использовались:

| Настройка | Значение |
| --- | --- |
| Разрешение и частота | 2560×1440, 60 FPS |
| Битрейт | 40 Мбит/с |
| Кодек и декодер | H.264, software |
| Вывод | полноэкранный, SDL/OpenGL |
| V-Sync и frame pacing | выключены |
| HDR и YUV 4:4:4 | выключены |
| Мышь | относительный режим |
| Системные клавиши | захват всегда |

На другой машине начните с 1920×1080, 60 FPS и 20 Мбит/с, затем повышайте разрешение. В Moonlight 6.2.0 стандартный macOS-рендерер изменился на libplacebo/MoltenVK; старому Mac может потребоваться другой выбор в расширенных настройках. Это отмечено в [описании релиза](https://github.com/moonlight-stream/moonlight-qt/releases/tag/v6.2.0).

Пример запуска уже сопряжённого компьютера. Адрес замените своим; `Desktop` должен присутствовать в списке приложений Sunshine:

```bash
env QSG_RHI_BACKEND=opengl VT_FORCE_METAL=0 SDL_RENDER_DRIVER=opengl \
  /Applications/Moonlight.app/Contents/MacOS/Moonlight stream \
  --resolution 2560x1440 --fps 60 --bitrate 40000 \
  --video-codec H.264 --video-decoder software \
  --display-mode fullscreen --no-vsync --no-frame-pacing \
  --no-absolute-mouse --capture-system-keys always \
  --no-hdr --no-yuv444 --no-quit-after --keep-awake \
  192.168.50.1 Desktop
```

Переменные задают проверенные предпочтения графического пути. После запуска всё равно проверьте фактически выбранные декодер и рендерер. Отключённая вертикальная синхронизация может дать разрывы изображения при движении.

## Мышь, клавиатура и возврат в macOS

Относительный режим мыши позволяет двигать курсор по всему рабочему столу Windows, включая физический монитор. Абсолютный режим может ограничить координаты областью передаваемого экрана. Курсор, ушедший на физический монитор, исчезнет с изображения iMac; верните его через соответствующую границу.

Запомните сочетания Moonlight: `Ctrl+Alt+Shift+Z` освобождает или захватывает ввод, `Ctrl+Alt+Shift+X` меняет полноэкранный режим, `Ctrl+Alt+Shift+Q` завершает поток, оставляя программу на Windows работающей. На клавиатуре Mac Alt обозначен Option. Сочетания перечислены в [разделе управления Moonlight](https://github.com/moonlight-stream/moonlight-docs/wiki/Setup-Guide#keyboardmousegamepad-input-options). При включённом supervisor завершённый поток может автоматически открыться снова.

## Чёткость текста и задержка

Для чёткости сначала сопоставьте три значения: размер рабочего стола Windows, разрешение видеопотока и размер панели iMac. Здесь все три должны быть 2560×1440. Поток 1440p из рабочего стола 1080p увеличивает уже готовые пиксели. Повышение битрейта не вернёт отсутствующие детали.

40 Мбит/с служат проверенной отправной точкой. При недостатке пропускной способности Wi-Fi больший битрейт добавляет потери и рывки. H.264 с обычной цветовой субдискретизацией также может смягчать мелкий цветной текст. Проверьте обычный документ, прокрутку и движение окна, а не только неподвижный фон.

Включите статистику сочетанием `Ctrl+Alt+Shift+S`. Смотрите потери кадров, сетевую задержку, время обработки на сервере, декодирования и вывода. Это разные участки пути. RTT, network latency и host processing не равны полной задержке от движения мыши до света на экране. Заявленные 60 FPS также не означают, что неподвижный рабочий стол постоянно обновляется 60 раз в секунду.

## Автозапуск в проверенной установке

На конкретном Mac настроен пользовательский LaunchAgent: он запускает Moonlight после входа в графическую сессию и перезапускает оборвавшийся поток. Supervisor предпочитает провод, ждёт 10 секунд недоступности активного адреса, повторяет подключение через 3 секунды и возвращается с Wi-Fi после трёх успешных проверок провода. Дополнительно используется `caffeinate -di`, чтобы сеанс не засыпал от бездействия.

Перед запуском закрепляется выбранный адрес в существующей записи Moonlight. Это устранило обнаруженное подключение по Wi-Fi при проводном адресе в команде. Такая автоматика привязана к одной записи компьютера и именам интерфейсов. Репозиторий не содержит её универсального установщика. Sunshine запускается штатным способом Windows; для смены источника захвата в нашей установке есть отдельная персональная настройка.

Автовход macOS настраивается вручную и зависит от FileVault. Без него сначала потребуется вход пользователя. Блокировка и запрос пароля остаются отдельными настройками; `caffeinate` их не отменяет. Холодный запуск, пробуждение и повторный вход нужно проверить отдельно перед постоянным использованием.

## Дублирование и безопасное восстановление

На проверенном ПК дублирование объединяло экраны в рабочий стол 1920×1080. На iMac он масштабировался и выглядел менее чётким. При этом менялись источник захвата и кодировщик, поэтому разницу задержки нельзя приписать только QSV или только clone. Рабочий вариант с исходным 1440p в дублировании не подтверждён. Для текста используйте проверенный расширенный режим.

Если изображение пропало, освободите ввод и проверьте, что Windows всё ещё видит виртуальный экран. Верните «Расширить», разрешение 2560×1440/60 Гц и нужный источник Sunshine. Затем переподключитесь. При рывках сначала проверьте потери и провод, затем временно уменьшите битрейт. При ошибке рендерера вернитесь к H.264, software и SDL/OpenGL.

Сохраните значения до изменений и меняйте по одному параметру. Не удаляйте драйверы и конфигурацию ради первого сбоя, не сбрасывайте сопряжение без причины. После удачного теста отдельно проверьте возврат кабеля, перезапуск клиента и полный запуск системы.

## Камера

Камера передаётся отдельно от рабочего стола. Проверена встроенная FaceTime HD: захват 1280×720 при 29,97 кадра/с, выход Windows 1280×720 при 30 FPS. Микрофон в этот поток не включён. Путь выглядит так: камера Mac → FFmpeg → прямой Ethernet → медиаисточник OBS на Windows → OBS Virtual Camera → приложение видеосвязи.

На Mac установлен FFmpeg 9.0.2 для Intel из сборки evermeet, на которую ссылается [официальная страница FFmpeg](https://ffmpeg.org/download.html). Перед установкой архив проверен по подписи сборщика. Доступ к камере был разрешён в штатном окне macOS для Терминала. Не запускайте захват впервые из SSH в расчёте, что разрешение появится само: откройте команду в графическом Терминале Mac.

Для повторения сначала подготовьте отдельный профиль и коллекцию сцен OBS с простым именем `iMac Camera`. В «Настройки → Видео» задайте холст и выход 1280×720, 30 FPS. Создайте один «Медиаисточник», снимите флажок «Локальный файл», задайте вход `tcp://192.168.50.2:5000` и формат входа `mpegts`. Адрес замените проводным адресом своего Mac. Установите повтор подключения через 1 секунду, если этот параметр доступен. В этой сцене достаточно одного источника видео.

На Mac выберите встроенную камеру в списке устройств AVFoundation. В проверенной машине это индекс 0. Индекс на другом Mac может отличаться. Пример команды при уже установленном FFmpeg; она запускается в Терминале Mac:

```bash
ffmpeg -hide_banner -loglevel warning -nostats \
  -f avfoundation -framerate 29.97 -video_size 1280x720 \
  -pixel_format uyvy422 -i '0:none' -an \
  -c:v libx264 -preset ultrafast -tune zerolatency \
  -threads 2 -pix_fmt yuv420p -b:v 3000k -maxrate 3000k \
  -bufsize 1000k -g 30 -keyint_min 30 -sc_threshold 0 \
  -flush_packets 1 -muxdelay 0 -muxpreload 0 -f mpegts \
  'tcp://192.168.50.2:5000?listen=1&tcp_nodelay=1'
```

Сервер слушает только проводной адрес Mac. Это соединение без авторизации, поэтому не заменяйте адрес на `0.0.0.0` и не открывайте порт в интернет. Оно принимает одного клиента: им должен быть OBS. Проверка порта отдельным клиентом может занять подключение. После разрыва в ручном варианте команду нужно запустить повторно.

В OBS нажмите «Запустить виртуальную камеру». Затем в предпросмотре Telegram, Discord, Zoom или другого приложения выберите `OBS Virtual Camera`. Звонок для проверки не нужен. Windows получила через это устройство 92 кадра в 1280×720 за контрольный захват. Пользователь также подтвердил изображение с iMac в предпросмотре приложения на ПК; совместимость с другими приложениями следует проверить в их настройках видео.

В персональной установке на рабочем столе ПК созданы ярлыки «Включить камеру iMac» и «Выключить камеру iMac». Первый запускает захват на Mac и профиль OBS, второй останавливает захват на Mac. Если OBS уже работает с другой коллекцией, сначала закройте его. Выключение источника не закрывает OBS: виртуальное устройство может остаться в списке приложений. В ручной настройке камера останавливается сочетанием Ctrl+C в её Терминале на Mac; прекращение видеозвонка само по себе её не выключает. Автозапуск камеры при загрузке не включён.

Если OBS после сбоя ждёт подтверждения запуска, откройте его обычным ярлыком, обработайте предупреждение и выберите профиль и коллекцию `iMac Camera`. Параметры запуска OBS используют отображаемые имена, поэтому проверьте, что выбрана сцена только с камерой iMac.

Здесь проверен проводной вариант. Wi-Fi для камеры, микрофон и полная задержка видеозвонка не проверены. Кодирование камеры добавляет нагрузку на процессор iMac. Увеличение выхода OBS до 1080p не добавит деталей исходной камере 720p. Справка: [AVFoundation](https://ffmpeg.org/ffmpeg-devices.html#avfoundation), [сетевой TCP FFmpeg](https://www.ffmpeg.org/ffmpeg-protocols.html#tcp), [виртуальная камера OBS](https://obsproject.com/kb/virtual-camera-guide).

## Публикация своей конфигурации

Не добавляйте в Git SSH-ключи, пароли Sunshine, PIN, сертификаты Moonlight, файлы сопряжения и полные журналы. Журналы могут содержать URL с ключами сеанса. Для примеров заменяйте имя компьютера, пользователя, локальные адреса и GUID. Проверяйте также историю коммитов: удаления секрета из последнего файла недостаточно.

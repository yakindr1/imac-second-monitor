# Порядок работы для ИИ-агента

Цель: отдельный рабочий стол Windows на экране iMac с сохранением обычного основного монитора. Переносимое окно должно появляться на iMac. Мышь и клавиатура iMac могут управлять Windows через Moonlight.

Схема: **Windows + виртуальный дисплей → Sunshine → Ethernet или Wi-Fi → Moonlight на iMac**. SSH нужен для настройки и управления процессами. Он не передаёт изображение экрана. HDMI-вход и перепрошивка не используются.

Репозиторий содержит знания и примеры. Готового универсального установщика в нём нет. Локальный агент выполняет работу инструментами своей среды. Если у него нет доступа к Windows, файлам или SSH, он должен прямо назвать недостающий доступ, а не заявлять о выполненной настройке.

## 1. Обследуй систему и сохрани исходное состояние

На Windows собери версию и архитектуру ОС, модели GPU, список активных дисплеев с физическими разрешениями и частотами, адаптеры и маршруты. Проверь установленные Sunshine, Moonlight и виртуальные дисплеи, состояние служб и имеющиеся правила брандмауэра. Не выводи полный список командных строк всех процессов: он может содержать чужие секреты.

На Mac узнай модель, размер и разрешение панели, версию macOS, архитектуру, GPU, наличие графической пользовательской сессии, сетевые интерфейсы и Moonlight. Полезные команды для обследования:

```sh
sw_vers
system_profiler SPHardwareDataType SPDisplaysDataType
networksetup -listallhardwareports
```

Сохрани локально копии меняемых конфигураций и значения сети, дисплеев и автозапуска. Составь короткий план по найденной системе. Не публикуй полный `system_profiler`: в нём есть серийный номер и другие идентификаторы.

Если экран уже работает, сначала проверь его. Не перезапускай поток, службу или драйвер во время работы пользователя без согласованного перерыва. Не удаляй установленные Parsec, Immersed и другие виртуальные дисплеи только потому, что они не относятся к этой схеме.

### Граница проверенной конфигурации

Пример в этом репозитории проверен на iMac 27″ Mid 2011, i7-2600, Radeon HD 6970M и панели 2560×1440. На нём уже стояла Ventura 13.5.1 с OCLP 0.6.8. Это не штатная поддержка Ventura моделью 2011 года и не инструкция установить её на любой iMac.

Проверенные версии: Windows 11, Sunshine 2026.914.233613, Virtual Display Driver 25.7.23 beta, Moonlight Qt 6.2.0. Повторение на другой ОС и другом GPU требует проверки совместимости. Не обновляй рабочую ОС или OCLP ради совпадения с примером.

## 2. Подготовь доступ к Mac

Попроси пользователя включить «Удалённый вход» и разрешить доступ только своей учётной записи. В Ventura путь: «Системные настройки → Основные → Общий доступ → Удалённый вход». В более старой macOS это отдельная панель «Общий доступ». Названия зависят от версии и языка системы.

Узнай имя пользователя и доступный адрес Mac. Если у учётной записи нет пароля, пользователь задаёт его в локальных настройках. Не проси присылать пароль в чат и не помещай его в команду, файл или журнал.

При первом SSH-подключении сверь ключ хоста с Mac через независимый локальный просмотр. Для Ed25519 отпечаток можно посмотреть в Терминале самого Mac командой `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` и сравнить с запросом клиента. Не используй `StrictHostKeyChecking=no`. Затем создай отдельную пару ключей для этой настройки и установи только открытый ключ через разрешённый интерактивный сеанс. Длинный ключ копируй инструментами, не заставляй пользователя набирать его вручную. Частный ключ и `known_hosts` храни вне репозитория с доступом владельца.

Если позже для того же Mac добавляется второй адрес, проверь, что он принадлежит той же машине. При использовании `HostKeyAlias` привяжи оба пути к уже проверенному ключу. Смена IP не является основанием молча принять другой ключ хоста.

Установку драйвера Windows, разрешения macOS и системные запросы пароля пользователь подтверждает в штатных окнах. SSH не обходит эти запросы.

Если первого сетевого доступа ещё нет, не пытайся менять Mac по недоступному SSH. Самый короткий путь: оба компьютера в одной домашней сети, затем проверка доступного адреса Mac. При единственном прямом кабеле сначала проверь автоматически назначенные link-local адреса и маршрут. Если они не дают связи, подготовь пользователю один короткий локальный шаг для сетевых настроек Mac; параметры Windows агент назначает сам. После доступа переходи к постоянной проводной подсети. Не выдавай отсутствие доступа за выполненную настройку.

## 3. Выбери сеть

### Оба компьютера подключены к роутеру

Используй их адреса в одной локальной сети. Ethernet предпочтителен для первого теста. Убедись, что клиентская изоляция Wi-Fi не мешает связи. Не меняй домашний шлюз и DNS, если сеть уже работает.

### Прямой кабель между ПК и iMac

Найди именно подключённые Ethernet-адаптеры на обеих сторонах. Проверь линк. Wi-Fi можно сохранить для интернета. Выбери отдельную подсеть, которая не пересекается с домашней сетью, VPN, виртуальными адаптерами и существующими маршрутами.

Пример только после проверки отсутствия пересечений:

| Параметр | Windows Ethernet | iMac Ethernet |
| --- | --- | --- |
| IPv4 | `192.168.50.1` | `192.168.50.2` |
| Маска | `255.255.255.252` (`/30`) | `255.255.255.252` (`/30`) |
| Шлюз | не задавать | не задавать |
| DNS | не задавать | не задавать |

Не копируй имена `Ethernet` или `en0` вслепую. После назначения проверь связь в обе стороны и сохранение интернета. Разреши Sunshine входящие соединения только для нужной локальной сети. Не отключай брандмауэр целиком, не настраивай проброс портов роутера и не открывай SSH в интернет.

Для SSH добавь проверенный проводной адрес. После первичного запуска потока подтверди фактический сетевой маршрут и адрес удалённого узла. В нашей установке один только IP в команде Moonlight не гарантировал использование провода: клиент выбирал сохранённый адрес из своей записи компьютера.

### Wi-Fi как резерв

Добавляй резерв после рабочего проводного сеанса. Используй стабильный адрес через DHCP reservation или проверенное локальное имя, например `WORKSTATION.local`. Проверь, что имя разрешается там, где будет работать клиент. Сохранённый случайный DHCP-адрес со временем меняется.

В персональной установке supervisor переключал запись Moonlight между проверенными адресами и отключал её mDNS-обнаружение. Это зависит от формата настроек конкретной версии. Не редактируй неизвестные ключи клиента без резервной копии и проверки; не выдавай этот приём за универсальный параметр CLI.

## 4. Установи только недостающие компоненты

Сверь официальную документацию выбранных версий, требования к ОС, архитектуру пакетов и подписи. Используй официальные релизы. Проверенная версия из таблицы выше является ориентиром воспроизведения, а не обещанием быть самой новой или подходящей для другой ОС.

- [Sunshine: официальный проект и релизы](https://github.com/LizardByte/Sunshine/releases).
- [Moonlight Qt: официальный проект и релизы](https://github.com/moonlight-stream/moonlight-qt/releases).
- [Virtual Display Driver: официальный проект](https://github.com/VirtualDrivers/Virtual-Display-Driver).

Sunshine устанавливается на Windows, Moonlight на Mac. Нужен виртуальный видеодисплей, если требуется отдельный рабочий стол. Виртуальный аудиодрайвер для этой задачи не требуется. На Windows ARM не используй x64-драйвер из примера. Не включай test signing и не отключай проверку подписи драйверов ради установки.

После установки Moonlight в «Программы» проверь его запуск в графической сессии Mac. Не отключай Gatekeeper ради неизвестной сборки. Если текущая macOS несовместима с доступным клиентом, остановись на этой причине и предложи совместимый подтверждённый вариант. Не начинай переустановку ОС без отдельной задачи пользователя.

## 5. Сопряги Moonlight с Sunshine

Открой локальную панель Sunshine на Windows. В стандартной установке это `https://localhost:47990/`. Пользователь создаёт собственные данные входа в локальной форме. Предупреждение о сертификате допустимо только после проверки, что открыт именно локальный Sunshine.

На Mac добавь адрес Windows в Moonlight. Инициируй сопряжение и подтверди показанный PIN через панель Sunshine. PIN передаётся только в рамках этого локального сопряжения. Не копируй чужие сертификаты и записи уже сопряжённого компьютера.

Проверь тестовый запуск `Desktop`, сначала с основным экраном Windows. Это доказывает транспорт, сопряжение и декодирование. Затем переходи к отдельному дисплею.

Официальная [инструкция Moonlight](https://github.com/moonlight-stream/moonlight-docs/wiki/Setup-Guide) описывает сопряжение и передачу всего рабочего стола.

## 6. Создай отдельный рабочий стол

В Windows открой «Параметры → Система → Дисплей». Определи физический и виртуальный экраны по обнаруженным данным. Номер дисплея и GDI-имя меняются, поэтому чужие `DISPLAY` и GUID не подходят.

Выбери «Расширить эти экраны». Физический экран оставь основным, виртуальный расположи в удобную сторону. Установи физическое разрешение панели iMac и подходящую частоту. Для проверенного 27″ Mid 2011 это 2560×1440 и 60 Гц. Другому размеру или модели эти значения не навязывай.

Учитывай масштабирование Windows: DPI-unaware инструмент может сообщать логические размеры вместо физических пикселей. Подтверждай режим через сведения дисплея или DPI-aware API, а не делай вывод о потере разрешения по одному такому отчёту.

Выбери в Sunshine именно виртуальный экран. Для проверенной версии `output_name` задаётся его обнаруженным `device_id`/GUID. См. [документацию Sunshine](https://docs.lizardbyte.dev/projects/sunshine/v2026.914.233613/md_docs_2configuration.html#output_name). Не используй GUID из другого компьютера.

Если режимами управляет Windows, в проверенной версии использовалось `dd_configuration_option = disabled`. Сначала проверь значение и смысл параметра в установленной версии. Не смешивай автоматическое перестроение Sunshine с независимым контроллером режимов.

Предпочитай штатный интерфейс настройки. Если правишь файл или вызываешь API, сохрани прежнюю конфигурацию и меняй только нужные поля. Частичное тело API может заменить весь конфиг. Не отправляй его без понимания семантики выбранной версии. При необходимости перезапуска согласуй краткий разрыв активного сеанса.

## 7. Настрой изображение и ввод

На другой машине начни с H.264, 1920×1080, 60 FPS и 20 Мбит/с. После успешного теста доведи рабочий стол Windows и поток до физического разрешения панели. Для чёткого текста разрешения источника, потока и панели должны совпадать. Если интерфейс мелкий, меняй масштаб Windows, сохраняя разрешение.

Проверенный профиль для Radeon HD 6970M на указанной Ventura:

| Настройка Moonlight | Проверенное значение |
| --- | --- |
| Поток | 2560×1440, 60 FPS |
| Битрейт | 40 Мбит/с |
| Кодек / декодер | H.264 / software |
| Вывод | SDL/OpenGL, полноэкранный режим |
| HDR / YUV 4:4:4 | выключены |
| V-Sync / frame pacing | выключены |
| Мышь / системные клавиши | относительная / захват всегда |

Это результат одной машины. Отключённая V-Sync может давать разрывы изображения. На другой графике сначала проверь доступное аппаратное декодирование и реальный рендерер. NVENC на Windows отвечает за кодирование и не включает аппаратный декодер на Mac.

В Moonlight 6.2.0 изменился стандартный рендерер macOS; на старой графике проверь альтернативный путь SDL в расширенных настройках. См. [заметки версии](https://github.com/moonlight-stream/moonlight-qt/releases/tag/v6.2.0). Параметры CLI узнавай через `--help` установленной сборки. Проверенная командная строка приведена в [подробном справочнике](guide.ru.md#настройки-moonlight-для-старой-radeon).

Убедись, что работает аппаратный кодировщик Windows, если GPU его поддерживает. Проверяй выбранный кодировщик по коротким очищенным диагностическим строкам. Не публикуй весь журнал Moonlight: он может содержать URL с ключами сеанса.

Проверь мышь и клавиатуру Mac на обоих экранах Windows. Относительный режим позволяет пересекать границу передаваемого дисплея. Расскажи пользователю, что курсор на основном мониторе может исчезнуть с iMac. Для освобождения ввода Moonlight использует `Ctrl+Alt+Shift+Z`, для завершения потока `Ctrl+Alt+Shift+Q`. На Mac Alt называется Option. Проверяй сочетания в версии клиента.

## 8. Проверь результат до автозапуска

Проверь всё ниже и зафиксируй только фактически полученные результаты:

- Окно переносится с физического дисплея Windows на iMac и обратно. Это расширение, а не повтор основного экрана.
- Обычный документ с мелким текстом читается; разрешения источника, потока и панели совпадают.
- Прокрутка и движение окна не дают постоянных рывков. Статистика Moonlight (`Ctrl+Alt+Shift+S`) помогает разделить сеть, обработку на сервере, декодирование и вывод.
- Фактический трафик идёт через выбранный интерфейс. RTT или значение network latency не называй полной задержкой от мыши до экрана.
- Мышь и клавиатура Mac управляют Windows; пользователь знает возврат к macOS.
- После согласованной остановки старого потока запускается новый. Подтверди реальную остановку, затем новую сессию и изображение. Прежний статус «подключён» и второй запуск уже открытого окна приложения этого не доказывают.

В нашем примере дублирование переводило рабочий стол в 1920×1080 и меняло путь захвата/кодирования. Нативное дублирование 1440p не подтверждено. Для текста используй расширение. При рывках сначала проверь линк, потери и декодирование; затем пробуй меньший битрейт. Повышение битрейта не восстанавливает детали источника низкого разрешения.

## 9. Добавь простой повторный запуск

Только после рабочего ручного сеанса настрой Sunshine штатным способом Windows. На Mac запускай Moonlight в графической сессии пользователя. Для автоматического повтора можно создать отдельный пользовательский LaunchAgent и supervisor с ограниченной частотой попыток. Не запускай параллельно несколько supervisor и клиентов.

Нужны корректные пути с пробелами, текущий UID вместо чужого номера, отдельные имена файлов и завершение только собственных дочерних процессов. Команда остановки должна останавливать и автоматический перезапуск, иначе Moonlight откроется снова. Сохрани прежние ярлыки и агенты, удаляй только созданные этой настройкой.

Автовход macOS настраивает сам пользователь в штатном окне. Объясни, что он меняет доступ к локальной учётной записи; не отключай FileVault автоматически ради автологина. Без автологина потребуется вход на Mac. `caffeinate` мешает засыпанию от бездействия, но не заменяет вход и не отменяет блокировку.

Если нужен резерв Wi-Fi, отдельно проверь отключение кабеля, переход на Wi-Fi и возврат на кабель. Затем проверь выход/вход, сон/пробуждение и полный запуск обоих компьютеров после выключения. В исходной установке холодный запуск ещё не подтверждён. Не обещай его на основании одного повторного запуска приложения.

## 10. Оставь пользователю результат и откат

В финале назови способ обычного запуска, способ остановки, выбранное разрешение и сеть. Отдельно перечисли непроверенные сценарии. Не включай камеру в эту задачу.

Откат должен возвращать сохранённые сетевые параметры и конфигурацию Sunshine, отключать созданный автозапуск и возвращать исходную раскладку дисплеев. Удаляй только собственные добавления после проверки их принадлежности. Не останавливай чужие процессы и не удаляй существующие драйверы. Сохранённые резервные копии содержат настройки доступа и остаются локальными.

Открытый репозиторий должен содержать лишь обезличенные инструкции. Не публикуй SSH-ключи, пароли, PIN, сертификаты, сопряжение, реальные имена пользователей/компьютеров, серийные номера, GUID и полные журналы. Проверь также историю Git и вложенные изображения.
